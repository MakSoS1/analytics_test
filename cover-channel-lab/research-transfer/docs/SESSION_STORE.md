# Поиск офисных сессий по времени

`office_session_store.py` публикует каждую проверенную порцию в один логический
Parquet-набор. Каждая строка сохраняет **все исходные признаки сегмента** и
дополняется `run_id`, `batch_id`, глобальными ключами сессии и сегмента,
`segment_start_utc`, `segment_end_utc` и датой начала в UTC. Физический путь:
`event_date=YYYY-MM-DD/run_id=.../batch_id=...`. Повторная публикация
существующей порции сверяет число строк, уникальность сегментов и число пакетов
и не добавляет дубли. В автоматическом конвейере дополнительно сверяется
SHA-256 описи исходных CSV; другой источник с тем же `batch_id` будет отвергнут.
Новая порция сначала записывается в скрытый временный каталог и становится
видимой читателям только после сверки.

На тестовом Jupyter набор расположен в
`~/work/office_iter/test-session-store-20260924/office_sessions.parquet`.
Скрипт находится в
`~/work/office_iter/bin/session_store_test_20260924/office_session_store.py`.
В нём 61 357 строк исходного 10-минутного прогона и 500 строк образца из
исправленного 141-столбцового Parquet под другим `run_id`. Чтение объединяет
схемы порций: новые признаки видны, у старого прогона они будут `NULL`.
На 500 строках все 141 исходных поля сверены построчно, включая массивы.

Примеры в Jupyter:

```bash
python3 ~/work/office_iter/bin/session_store_test_20260924/office_session_store.py \
  range \
  --root ~/work/office_iter/test-session-store-20260924/office_sessions.parquet \
  --start-utc 2026-09-23T16:15:00Z --end-utc 2026-09-23T16:16:00Z --limit 10

python3 ~/work/office_iter/bin/session_store_test_20260924/office_session_store.py \
  session \
  --root ~/work/office_iter/test-session-store-20260924/office_sessions.parquet \
  --run-id check10m-20260923T161229Z \
  --session-uid '365a9ef7e9eb7e3a#34'
```

`range` ищет пересечение с интервалом `[start, end)`; затем `session` по паре
`run_id` + `session_uid` возвращает **все сегменты**, в том числе из других
порций. Для получения полной таблицы признаков этой сессии можно добавить
`--export-parquet /новый/путь`; существующий путь не перезаписывается. Часть
признаков (например, квантили) нельзя складывать по сегментам. До отдельного
пересчёта полного профиля их следует интерпретировать как признаки сегмента.

Для следующего прогона на текущем Jupyter публикация включается явно через
`OFFICE_SESSION_STORE_ROOT=work/office_iter/session-store` при запуске
`office_autopilot.sh`. Без этой переменной прежний путь обработки не меняется.
Набор дублирует широкую таблицу сессий, поэтому перед недельным прогоном
нужна оценка объёма по реальным трёхчасовым порциям и достаточный запас диска.
В этом тесте 10 минут заняли 91,2 МБ дополнительно при 36,9 ГиБ свободного
места в Jupyter; простая экстраполяция на неделю даёт около 92 ГБ только для
нового набора. Этот Jupyter по такому замеру для недельного дублирования мал.

Это тестовый набор на файловой системе Jupyter. Для общего управляемого
пространства Cosmolake потребуется выделенный каталог таблиц и транзакционная
публикация (например, Iceberg). Простое копирование этого каталога в S3 не
создаёт зарегистрированную таблицу Cosmolake и не даёт атомарности для
параллельных читателей. Тест не изменял живой захват и существующие наборы.
