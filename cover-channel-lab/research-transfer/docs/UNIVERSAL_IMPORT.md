# Общий перенос других сетевых техник

Сбор активности, перенос в фон и извлечение признаков разделены. Генератор может быть любым внешним инструментом: общий конвейер получает файлы захвата и подтверждения, а не запускает произвольные команды MITRE. Наблюдаемая техника определяется внешним генератором, не названием файла. Техники, которые не создают видимого сетевого обмена, этот конвейер оценить не может.

## 1. Соберите сценарий и обычный контроль

Одинаковые окружение, клиентский стек и путь для обеих ролей; независимые реальные исполнения. Нужны изолированные Ethernet PCAP целых TCP/UDP обменов: целые кадры, монотонное время, первый SYN от клиента у каждого TCP-потока, первый пакет клиента у UDP. ICMP, фрагменты и смешанные много-клиентские захваты требуют отдельного membership adapter: универсальный TCP/UDP вход честно их отклоняет.

Сохраните receipt, журнал клиента/сервера или иной факт выполнения. Адаптер проверяет хеши подтверждений, но не понимает смысл внешнего задания. Разметка остаётся утверждением оператора, подкреплённым evidence; не превращайте успешный exit code в доказательство техники.

## 2. Опишите activity.json

Пути относительно файла. Ниже структурный пример; замените SHA256 фактическими значениями. Для другой техники меняется только идентификатор/описание/источник; список Cover Channels не редактируется.

```json
{
  "activity_id": "TXXXX_lab_example",
  "pair_id": "profile_001",
  "capture_environment": "isolated",
  "dataset_role": "scenario_and_matched_control",
  "arms": {
    "scenario": {
      "source_ip": "10.20.0.11",
      "pcap": "scenario.pcap",
      "sha256": "ACTUAL_PCAP_SHA256",
      "description": "Фактически выполненная тестовая активность",
      "evidence": [{"path": "scenario_receipt.json", "sha256": "ACTUAL_RECEIPT_SHA256"}]
    },
    "control": {
      "source_ip": "10.20.0.11",
      "pcap": "control.pcap",
      "sha256": "ACTUAL_PCAP_SHA256",
      "description": "Проверенный обычный контроль в той же среде",
      "evidence": [{"path": "control_receipt.json", "sha256": "ACTUAL_RECEIPT_SHA256"}]
    }
  }
}
```

Для двух обычных негативов задайте `dataset_role: hard_negative`. Не объявляйте неуспешные/непроверенные сценарии benign. При измеренной и объявленной среде можно добавить `path_profile`; без объявления статус остаётся `not_declared`, не «проверено». Это проверка заявленной среды по самому PCAP, а не подгонка активности до нужного score.

```bash
cd cover-channel-lab/research-transfer
export PYTHONPATH="$PWD/code"
python -m office_injection.activity --spec /path/to/activity.json --out /path/to/NEW_PREPARED
```

Каталог связывает source pair, обе роли, хеши и observation. ID `TXXXX_lab_example` не требует изменений runtime. Импорт не переставляет/не удаляет неудобные пакеты.

## 3. Перенесите в существующий фон

Создайте `office_inputs.json` — JSON-массив уже имеющихся путей `.pkts`; рядом нужны соответствующие `.pay` одного поддерживаемого формата. Их получают штатным экспортом из сохранённых PCAP. В ZIP сырые PCAP и эти промежуточные файлы не входят: нужны ваши явно выбранные локальные входы.

```bash
python -m office_injection --catalog /path/to/NEW_PREPARED/catalog.json \
  --office-inputs /path/to/office_inputs.json \
  --out-dir /path/to/NEW_RUN --run-id custom_activity_001 \
  --repeats 6 --files-per-batch 2
```

Этот CLI использует изолированный RX replay исходной скорости. Требует Linux, tcpreplay/tcpdump/ip и sudo для собственного namespace; офисные интерфейсы не используются. Ограничение этого replay adapter — максимум 35 секунд, включая резерв 3 секунды. Длинные/другие carrier-захваты требуют отдельного явно проверяемого observation adapter; `--offline-fixture` предназначен для тестов и не заменяет настоящую RX-проверку. Остаток диска проверяется до run, входы и неудачные outputs сохраняются. Для большого фона используйте небольшие закреплённые окна вместо целого дня в одном run.

Результат полной схемы — `NEW_RUN/batches/*/parquet/office_sessions.parquet`; membership — `segment_gt.parquet`. Не берите вместо него `research_training/features_all.parquet`, если нужна полная схема: research baseline намеренно выбирает 89 X. Дополнительные метки соединяйте по global_segment_uid/global_session_uid и храните отдельно от признаков.

## 4. Проверяйте качество отдельно

Нужны чистая ветка на том же фоне и `office_injection.compare`, проверка original bytes/order/counts, отсутствие tuple collisions, подтверждённые роли и групповой split. Исходные приложения и их полезная нагрузка не изменяются ради похожего графика. Модель сенсора и среда — отдельные явно отмеченные исследовательские аппроксимации, не доказательство естественности.

Подробный исторический контракт: `universal_activity_generator.md`. В нём пути из исходного репозитория; команды этого документа соответствуют standalone layout ZIP.
