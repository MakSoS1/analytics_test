## Отбор и чистота источника

Отбираются TCP-сессии на портах назначения 80/443, в которых хотя бы один сегмент содержит ≥6 пакетов. Фиксированное ранжирование SHA256 идентификаторов выбирает первые 4 000 уникальных сессий каждого дня. **Все** сегменты выбранной сессии сохраняются, поэтому 28 сентября получилось 4 002 строки. Отбор не использует AUC, кластеры, значения TLS или сходство с генератором.

Исходные SHA256 сверены с ранее запечатанными `clean_reference` manifests. В обеих исходных таблицах `segment_gt` нет строк вставленного трафика. Использовались чистые источники, а не scenario/control композиции. Хеши и численность зафиксированы в [SELECTION_REPORT.json](SELECTION_REPORT.json). Воспроизводимый операторский скрипт: [sample_office_days.py](../../code/sample_office_days.py).

Это выборка веб-кандидатов, а не представительная выборка всех протоколов офиса. Порт 443 сам по себе не доказывает TLS. Офисная активность не проверена вручную как benign: исходные `y_presumed`/`label_source` оставлены для совместимости, не являются подтверждённой истинной меткой. Не используйте их как признаки.

## Разделение данных

- `capture_day_id`: один псевдоним дня на файл. Таблица выше и отчёт связывают его с календарной датой; это идентификатор разделения, а не сокрытие даты.
- `independent_source_group`: HMAC от пары день + исходный `host_key`. Объединяет все выбранные сессии клиента внутри дня. Это **приближение** независимой группы, не доказательство независимости машин/пользователей/кампаний: NAT и точное положение зеркала неизвестны.
- `source_session_group`: тот же псевдоним, что `global_session_uid`; связывает все сегменты одного соединения. Его нельзя разрывать между обучением и проверкой.

Для внешней проверки оставляйте целый день вне обучения. Внутри обучающего дня делите по `independent_source_group`, не по случайным строкам. Эти два дня уже использовались в диагностике исходного исследования; они дополнительные относительно первого офисного среза PR №58, **не ранее неизученный финальный holdout**. Не называйте результат на них независимым подтверждением production FPR.

В этой паре файлов один новый секретный HMAC-ключ. Словарь расшифровывается прежним ключом получателя, но псевдонимы **не совпадают автоматически** с выпуском 6 октября. Даже исходный `host_key` не гарантирует стабильную личность клиента между историческими захватами. Не объединяйте клиентские идентификаторы разных выпусков без разрешённой локальной проверки оригинальных словарей/соли.

## Ограничения измерений

TLS-поля 22 сентября отсутствуют в сохранённом источнике; пропуски не заменены нулями или синтетическими значениями. Все null-counts перечислены в отчёте. Сравнение TLS на этом дне некорректно; используйте его для транспортной/временной диагностики с явным указанием измеренного набора, а для TLS — 28 сентября. Не считайте различие масок пропусков доказательством отличия приложений и не подгоняйте новые значения для прохождения origin-аудита.

Подтверждённые сведения и неизвестные параметры зеркала, NAT, TLS-прокси, ОС клиентов и версий извлекателей перечислены в [capture_context.json](capture_context.json). Историческая документация описывает полный захват без BPF и GRO, но настройки именно этих файлов не перепроверены по сырым PCAP. Хеши опубликованных helpers идентифицируют текущий код для воспроизведения, а не доказывают тождество исторических бинарников.

**Новых Arkime-таблиц этих дней нет.** Уже опубликованные Arkime/SPI и сопоставление с конвейером за 23 сентября лежат в предыдущем выпуске. Эти две таблицы посчитаны пользовательским пакетным конвейером; их нельзя выдавать за native Arkime/Suricata/Zeek экспорт.

## Словарь и безопасность публикации

`dictionary.json.gpg` содержит обратимые соответствия и исходные Arrow-схемы, зашифрованные OpenPGP для получателя `32D37D34A82966137BA80C667163C26216F27937`. Приватный ключ и HMAC-ключ остаются на Mac, вне репозитория. Расшифровывайте только в разрешённый локальный каталог:

```bash
# Используйте локальный GPG home, в котором уже импортирован приватный ключ владельца.
gpg --output /private/tmp/office-days-dictionary.json --decrypt dictionary.json.gpg
python ../../code/pseudonymize_tables.py \
  --dictionary /private/tmp/office-days-dictionary.json \
  --input office_day_03.parquet \
  --out /private/tmp/office-day-03-restored.parquet
```

Не публикуйте расшифрованные файлы. [DATA_MANIFEST.json](DATA_MANIFEST.json) содержит хеши файлов, численных колонок и результат восстановления **из фактического ciphertext** всех значений и полных схем. Исходные PCAP, IP-словарь открытым текстом, sidecars, ключи и адреса исследовательских машин не включены. Точные времена, порты, статистика и связи между псевдонимами остаются потенциально идентифицирующими: это псевдонимизация, не гарантия анонимности.

Естественность генератора и качество будущей модели этим выпуском не подтверждены. Выпуск добавляет реальные измерения и воспроизводимые ограничения для следующего исследователя; прежние AUC из PR №58 на новых днях здесь не пересчитывались.
