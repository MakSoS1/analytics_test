# Remote Admin Anomaly V1 — Research Corrections

## What was valid in the original study

The original research correctly identified that Remote Services detection cannot be reduced to one port or one payload signature. Its useful parts retained in V1 are the protocol taxonomy, separation of flow/packet/window/host context, temporal windows, persona/role idea, benign administrative hard negatives, network impairments and the recommendation to combine Suricata with flow-based ML and cross-flow correlation.

## What was not a valid ML-quality experiment

The earlier 28-PCAP result (16 TP, 12 TN, zero FP/FN) is retained only as evidence that its handcrafted Suricata scenarios exercised the intended rule branches. Those PCAPs were deliberately constructed around the tested rule conditions, including trusted/untrusted address choices and expected SIDs. Therefore `Precision=Recall=1.0` on that set cannot be interpreted as generalization quality of a remote-admin anomaly model.

The old packet builders are useful as protocol/rule regression fixtures, but they do not replace real application/kernel network behavior for ML training.

## Corrections implemented in V1

### 1. Real wire before feature extraction

Primary traffic is generated by real processes in isolated namespaces: OpenSSH, Samba, xrdp/FreeRDP and TigerVNC/RFB after their fidelity gates. Full `tcpdump -s 0` capture starts before scenario execution. Synthetic protocol bytes are not substituted when a real implementation fails.

### 2. Ground truth is independent from Suricata

The orchestrator writes planned/executed session manifests. Suricata and Zeek consume the PCAP afterward. A Suricata alert can be compared with ground truth but can never create or change the class label.

### 3. No `external IP = attack` shortcut

The topology is entirely lab-internal and both benign/suspicious scenarios use the same address space and network impairment families. Address identity, role identity and raw host IDs are forbidden model inputs.

### 4. Generator nuisance is not a production feature

`netem_profile`, injected delay/loss/reorder/rate/MTU, generator seed, scenario ID, campaign ID, expected SID and fidelity tags are retained for analysis only. They are forbidden from the production model matrix.

### 5. PCAP is never disposable after feature extraction

Bronze retains the complete `.pcap.zst`, manifests, reproducibility metadata and checksums. Silver and Gold are derived products and can be regenerated when parsers or features change.

### 6. Many TCP flows may belong to one behavioral session

The first real smoke demonstrated this directly: 40 behavioral sessions generated 102 parser-observed TCP connections. The pipeline therefore records an explicit many-flow/session mapping instead of inventing a one-row/one-flow assumption.

### 7. Production model unit is a parser-observed flow

Behavioral-session Gold remains useful for research aggregation, but an NGFW cannot observe orchestrator session boundaries. The promoted production model is rebuilt from Zeek/Suricata-observable flows with prior-only rolling/window/graph state. The orchestrator contributes only labels and grouped split membership.

### 8. Split is grouped and global

Random row splitting is prohibited. Campaigns and counterfactual pairs remain in one split. Global post-shard splitting also creates unseen source-host, unseen host-pair and temporal holdouts. Stage H/partial WinRM is forced to challenge before final promotion.

### 9. Fidelity claims are explicit

- SSH: real OpenSSH wire.
- SMB: real Samba/smbclient wire.
- RDP: Linux xrdp/FreeRDP wire; never claimed to be native Windows desktop semantics.
- VNC: real RFB server wire; interaction fidelity is explicitly bounded.
- DCE/RPC via Samba/rpcclient: `partial_dcom` fidelity evidence only, not native DCOM/TCP-135 train data.
- WS-Man fixture: `partial_winrm`, challenge only.
- Native Windows DCOM/WinRM: deferred to a Windows fidelity holdout.

### 10. Complex C2 framework traffic is deliberately excluded from V1

Sliver, Mythic, Havoc, Cobalt Strike and Metasploit-style payload traffic is not used in V1 training. Adding those now would risk teaching the classifier framework fingerprints rather than remote-admin behavioral anomaly. A later adversarial holdout can add bounded framework-derived traffic after the baseline is stable.

## Model interpretation

M0 is the deterministic/rule baseline. M1 LightGBM is the primary production behavioral classifier. M2 Isolation Forest is trained only on benign rows and initially operates in shadow mode. A later sequence model is justified only if flow + rolling/window/graph features leave a measurable gap on campaign-level holdouts.

## Scaling correction

The original `~201k sessions` number is now an upper scale envelope, not an acceptance criterion. Real-wire throughput, storage cost and learning curves determine whether to expand. The project must never generate lower-fidelity duplicate traffic solely to satisfy a row-count target.
