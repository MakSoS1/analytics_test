# Измеряемая подготовка повторного прогона

Этот overlay создан от harness commit `26adee18f960e1af7db7fe1a0d74642728916bbf` для новой ветки `qa/examclips-stand45-retry-observed-2026-11-15`. Полный manifest45, выбранные семь случаев EN03/enl07/enl03/enl08/enl05/enl02/enl06, TIB transport, приложение и его хэши, настройки UI и поведение полного case runner сохраняются. Добавляется наблюдение ресурсов непосредственно в подготовительном ASR gate.

## Причина

Run43768679942 завершился до матрицы: в обычном ASR25-секундного фрагмента RU03 зарегистрирован `ERR_BLOB_OUT_OF_MEMORY`. Те же байты фрагмента ранее прошли gate. Полный RU03 в persistent-режиме также завершился успешно, поэтому постоянный профиль сам по себе не объявляется причиной. В ошибочной подготовке не было снимка диска, origin quota и cgroup в момент отказа. Эта попытка не добавляет семь оценок качества.

## Обязательный gate и отдельный контроль

Основная попытка сохраняет свежий persistent context и четыре существующих флага Chrome. Полные случаи вызывают тот же helper. Для основного gate обязательны обычная загрузка видео, auto/full/standard, наблюдаемое processing, завершённый idle UI и реально сформированный непустой SRT. Только этот результат разрешает матрицу.

Если основной ASR действительно был запущен и завершился отказом, браузер успешно закрыт и остаётся минимум3.5мин, запускается один свежий nonpersistent control. Он использует тот же файл с повторной проверкой SHA-256, те же четыре флага и тот же UI-код. Его активная попытка ограничена3мин; watchdog закрывает браузер по deadline, после чего остаётся ограниченный сбор/закрытие в пределах30с резерва. Даже успешный control оставляет весь prepare failed и матрицу skipped. При недостатке времени, незакрытом первом браузере или ошибке до стартаASR контроль не выполняется; причина записывается явно.

Gate имеет внутренний общий бюджет16мин при прежнем Actions step ceiling18мин; ASR основного теста ограничен10мин. Активная основная попытка ограничена11мин, контроль3мин; на завершение оставлен отдельный30-секундный резерв. Обычный deadline, завершение браузера и шифрование доказательств сохраняются. Эта последовательная проверка не доказывает универсальную причинность режима браузера: время, кэш ОС и условия сети не являются контролируемыми константами.

## Что сохраняется

У каждой попытки отдельные JSON report, SRT/снимок, до20 resource rows и до80 Hub/Parakeet info events. Замеры идут до браузера, после готовности, перед моделями, до шести раз при прогрессе, при первом существенном Blob OOM и перед cleanup. `ERR_ABORTED` не расходует бюджет ошибок. Записываются statfs свободные байты/inode, host memory, MemAvailable, cgroup, origin estimate/persisted и main-page heap раздельно. Добавлены host CPU load averages и накопленные CPU ticks; они не названы загрузкой процесса Chrome.

Для persistent profile известен фактический путь. Для control read-only CDP извлекает только путь профиля из командной строки собственного браузера; вся командная строка не сохраняется. Если наблюдение недоступно, путь не угадывается: остаётся явно обозначенный tmp-parent и флаг отсутствия измерения. Cookies, БД или файлы профиля не читаются.

Origin quota и main-page heap не измеряют внутренний предел Blob storage или память worker/WASM. Неизвестные значения остаются неизвестными. Продукт, Blob/fetch/model code, память браузера, cache/state и production доступ не изменяются. Все подробные данные попадают только в прежние зашифрованные preparation artifacts. Публичный журнал содержит bounded status/counts/hashes.
