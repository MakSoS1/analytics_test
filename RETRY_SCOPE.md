# Отдельный повтор семи технически не завершённых источников

Этот пакет продолжает аудит исходных 45 лекций в отдельной ветке `qa/examclips-stand45-retry-2026-11-15`. Базовый harness: `7ece26b29ef27cd7eaa83cde2245efb90441bda9`. Работающий run `43765971939` сохраняется. Повтор запускается после review всего кандидата.

## Точный объём

`run-request.json` содержит `en03`, `enl07`, `enl03`, `enl08`, `enl05`, `enl02`, `enl06`. Шесть длинных TIB-случаев завершились ошибкой FFmpeg TLS при получении TIB HLS до начала приложения. EN03 завершился `ERR_BLOB_OUT_OF_MEMORY` при инициализации модели; причина пока не установлена. EN03 стоит первым, чтобы получить раннее наблюдение инициализации модели на полном источнике. Другие активные или ещё не выполненные случаи не добавлены. Матрица ограничена семью параллельными работами, без отмены прежних работ.

Полный исходный manifest из 45 случаев сохранён побайтно. Приложение остаётся private CI artifact `14177000950`, commit `c8358a6df86ca0f77d859ebe8481a876b3e1abd5`, SHA-256 архива `4463e4e2b9a3f57ce215610f974f2162189a4c421bab6947191dd61c1c726940`. Все 18 хэшей приложения, политика сети, отсутствие COEP, автоматический язык, полный ASR, стандартный экспорт и все клипы сохранены. Результаты имеют тип `test_instance`.

## Получение источника

Для открытых незашифрованных TIB VOD helper получает полные дорожки обычным HTTPS, сохраняет точные локальные playlists и передаёт их FFmpeg для stream-copy. Проверяются origin/redirect, полнота VOD, размеры byte ranges и допустимые пути; шифрованные, частичные или неоднозначные playlists отклоняются. Успешный полный контроль ENL03 дал прежний SHA-256 MP4 `d585eee79b191e748a423a1e9ac89ca31a4956f9a36c964c34ba26fb6949cc21`, 814500497 байт, 9606.484866 с, 1080p с AAC. Это подтверждает идентичность проверенного ENL03; хэш каждого другого источника оценивается по его фактическому результату после повтора.

## Браузер и измерения

Полные случаи сохраняют `launchPersistentContext`, прежние параметры и четыре флага Chrome. Подготовительный реальный ASR gate использует ту же функцию запуска и отдельный свежий persistent profile; это явное изменение относительно прежнего непостоянного smoke-контекста. Новых RAM-флагов, очистки кэша или состояния приложения нет. Gate требует фактически созданный непустой SRT и завершённый idle UI для 25-секундного диагностического фрагмента RU03; он не заменяет ни одного полного источника.

Read-only observer записывает максимум 20 замеров: до браузера, после готовности, после upload до ASR, до шести замеров подготовки модели, при существенной ошибке и перед cleanup. Сохраняются свободные байты/inode через `statfs` для профиля/tmp/source/evidence; host memory, Linux MemAvailable и cgroup memory отдельно; `navigator.storage.estimate()`, `persisted()` и main-page JS heap. Browser probe ограничен 2.5 с; фоновые замеры не ожидаются в ASR-поллере. Отсутствующие значения остаются `null` с явной причиной. Для ещё отсутствующего пути явно записано число переходов к существующему родителю. Содержимое профиля и БД не читается.

Штатные `ERR_ABORTED` не расходуют бюджет диагностических blob failures. Для первого `ERR_BLOB_OUT_OF_MEMORY` сохранён отдельный приоритет; app/page errors имеют свой лимит. Дополнительно сохраняются максимум 80 обычных info-сообщений Hub/Parakeet. Blob, fetch, IndexedDB и состояние модели не оборачиваются и не подменяются. JSONL и логи входят только в существующие зашифрованные evidence artifacts.

Origin quota не является лимитом Blob storage, а heap страницы не измеряет память worker/WASM или процесса Chrome. Замеры сами по себе не доказывают причину EN03.

## Разделение запусков и ключей

Новая ветка имеет собственные prepare/unlock descriptors и ciphertext commits. AAD строго связывает repository, новую branch, новый run, attempt и case; старую ветку helper отвергает. Root готовит отдельный одноразовый bundle RSA recipient и отдельный private operator directory, не меняя текущий watcher. Recovery recipient доказательств сохранён. Матрица получает приложение только после нового успешного prepare gate. Shared bundle attempt 1 нельзя использовать с AAD attempt 2: нужен новый workflow run с новым prepare.

Предыдущие ошибки и артефакты сохраняются. Итоговая карточка каждого исходного случая указывает конкретный run/attempt. Технический отказ не становится успешной проверкой приложения или новым отдельным случаем.
